## Overview

The tests directory aggregates a set of pytest-based modules and browser-driven end-to-end suites that validate a local API and workspace behaviors. At the repository root there are focused test modules: behavioral tests for local schemas and typed records (test_custom_databases.py), synthetic local integration tests for a specific API version (test_integrated_workspace_v09.py), branding and backward-compatibility checks for v0.11 (test_myai_v011.py), page block handling checks against a local FastAPI service (test_page_canvas_v10.py), and integration tests for workspace navigation around trash/restore and related search/page/template-tag interactions (test_workspace_navigation_v110.py). These root-level tests exercise both API behavior and workspace semantics in isolation and in integration.

A subdirectory named browser/ contains Chromium-driven end-to-end and acceptance test modules and helper harnesses that validate workspace UI flows across multiple versioned galleries. This directory is intended to complement the root pytest modules by providing UI-level validation of workspace behaviors and is grouped separately because of its reliance on browser-driven flows and a different execution surface. Together the root test modules and the browser subdirectory form a layered test suite: lightweight and synthetic integration tests at the root, and heavier acceptance/end-to-end browser tests in the browser/ subdirectory, providing broad coverage of API, page rendering, workspace navigation, and version-specific behaviors.


### File Organization

Root-level test modules are organized by the feature or scenario they exercise (databases/schemas, specific API version integrations, branding/backwards-compatibility, page canvas behavior, and workspace navigation). Browser-driven end-to-end tests live under browser/ to separate UI-focused flows and harnesses from local API and unit-level tests.
