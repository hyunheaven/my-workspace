# My Workspace v1.1.0-rc.1

기준 브랜치는 GitHub의 `main` 커밋 `0bf08f9`이며, 태그 `v1.0.0`은 `1705f8c`를 가리킵니다. GitHub Releases 목록은 조사 시점에 비어 있었습니다. 페이지와 업무 ID를 유지하는 추가 기능이므로 목표 버전은 v1.1.0으로 정했습니다. Windows 11 실기 검증 전의 작업 브랜치에는 후보 버전 표기를 사용합니다.

My Workspace는 개인 PC에서 문서, 업무, 일정을 정리하는 로컬 작업 공간입니다.

## 기준 버전 점검

| 기능 | 판정 | 최신 main에서 확인한 동작 |
| --- | --- | --- |
| 편집기 | 부분 구현 | 블록과 표, 슬래시 메뉴, 자동 저장, 버전 이력. 번호 목록, 내부 링크, 편집 초안 복구, 블록 편집 실행 취소가 필요했습니다. |
| 페이지 트리 | 부분 구현 | 하위 페이지, 이동과 순환 방지, 즐겨찾기와 최근 목록. ID 기반 페이지 주소와 휴지통이 필요했습니다. |
| 템플릿 | 사용 가능 | 272종의 기존 카탈로그. 템플릿 카드에서 블록이 포함된 페이지 생성과 편집이 가능했습니다. |
| 업무 데이터베이스 | 부분 구현 | 업무 표와 상태 보드가 같은 레코드를 사용했습니다. 업무 캘린더, 추가 속성과 상세 메모가 필요했습니다. |

| 검색 | 부분 구현 | 페이지 제목·본문·표·태그 검색. 업무 데이터가 검색 범위에서 빠져 있었습니다. |

| 데이터 저장 | 사용 가능 | 합성 데이터로 SQLite 저장 및 Linux 서버 재시작 후 복원을 확인했습니다. |
| Windows 11 한국어 IME | 환경상 미검증 | Windows 11 실기 실행과 Microsoft 한글 IME 검증은 별도입니다. |

## 저장과 복구

- 기존 SQLite 경로와 `EAW_DATA_DIR`를 사용합니다. 새 구조는 `page_trash`와 활성 문서 뷰, 블록 유형 확장 컬럼, 업무 속성 컬럼을 추가합니다. 기존 페이지·블록·업무 ID와 캘린더 업무 연결을 재생성하지 않습니다.
- 업무 마감일은 원래 업무 레코드에 저장합니다. 개인 캘린더의 업무 표시는 기존 투영을 사용합니다. 참고 주소는 평문 속성으로 저장합니다.
- 즐겨찾기·최근 목록·탭, 템플릿 즐겨찾기와 테마에 쓰던 브라우저 키를 사용합니다. 업무 뷰 설정은 `my-ai-workspace.task-views.v1`에 저장합니다. 편집 초안은 탭의 세션 저장소를 사용합니다. 저장 장애가 생기면 같은 탭에서 재시도할 수 있으며 탭을 닫기 전에 초안을 확인합니다.
- 구버전 복귀에는 업데이트 전 DB를 사용합니다. [Windows 실행 및 복사본 검증 절차](../RUN_LOCAL.md)

## 자동 검증

Linux에서 `python -m pytest -q`의 테스트 52개와 서브테스트 716개가 통과했습니다. Playwright와 Chromium에서 아래 다섯 스크립트가 통과했습니다. 테스트는 임시 SQLite 파일에 합성 데이터만 기록합니다.

| 스크립트 | 주요 검증 |
| --- | --- |
| `tests/browser/workspace_v012.py` | 기존 템플릿 생성, 슬래시 입력, 페이지 저장과 이력, 표·보드와 캘린더 |
| `tests/browser/workspace_v013.py` | 템플릿 검색과 즐겨찾기, 페이지 복제, 검색과 재실행 |
| `tests/browser/workspace_v014.py` | 고대비, 페이지 테마, 탭, 태그와 새로운 브라우저 세션 |
| `tests/browser/workspace_v110.py` | 한국어 템플릿 페이지와 서버 재시작, 표→보드→캘린더→표, 이동과 이름 변경 후 링크·검색·휴지통 복원 |
| `tests/browser/workspace_v110_canvas.py` | 저장 실패와 초안 복구, 리비전 충돌, 실행 취소·다시 실행, Chromium 조합 입력, 긴 한글 문서와 DB 경로별 초안 분리 |

실행 형식은 `python tests/browser/workspace_v110.py --chromium <Chromium 실행 파일>`입니다. 별도로 v1.0.0 태그에서 생성한 DB의 복사본을 마이그레이션했습니다. 기존 레코드와 외래 키가 유지됐고 원본 해시도 일치했습니다. 쓰기 잠금으로 시작이 실패하는 경우를 재현하고 기존 버전에서 백업이 열리는 것을 확인했습니다. 같은 브라우저 프로필을 사용한 업그레이드에서 고대비, 페이지 테마, 탭 색상, 태그, 페이지·템플릿 즐겨찾기도 복원됐습니다.

Windows 11의 PowerShell 실행, Microsoft 한글 IME, Edge/Chrome의 긴 문서 편집 반응은 실기 미검증입니다.

## 후속 우선순위

1. Windows 11 실기에서 세 가지 업무 흐름과 한국어 IME, 긴 문서 편집, 브라우저 설정 복원을 검증합니다.
2. 텍스트 편집의 중첩과 다중 블록 조작을 보강하고, 사용자 정의 데이터베이스 및 속성 스키마를 설계합니다.
3. P1에서 관계·롤업·수식·연결된 뷰·타임라인·갤러리, Markdown·CSV 가져오기와 내보내기를 단계별로 검증합니다. 기존 페이지 이력과 복원은 유지하며, 스냅샷 비교와 데이터베이스 이력은 별도 범위입니다.
4. 공유·권한·댓글·동시 편집은 향후 별도 서버 기능으로 검토합니다. 중앙 서버가 공유 데이터의 기준이며, 로컬 문서는 사용자가 명시적으로 게시합니다.
