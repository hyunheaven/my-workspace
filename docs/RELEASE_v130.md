# My Workspace v1.3.0

v1.2.0 후보 이후 사용자 정의 데이터베이스의 **레코드와 저장된 보기의 변경 이력·복원**을 추가했습니다.

## 사용 방법

| 작업 | 위치와 확인 방법 |
| --- | --- |
| 레코드 복원 | **내 데이터베이스 → 레코드 열기 → 변경 이력**. 제목, 메모, 입력한 속성을 현재 저장본과 비교하고 이전 버전을 복원합니다. |
| 보기 복원 | **내 데이터베이스 → 보기 설정 → 변경 이력**. 보기 이름·유형, 필터·정렬·그룹·날짜 설정을 비교하고 이전 버전을 복원합니다. |
| 입력 중 이력 확인 | 이력 창을 닫으면 편집 중인 입력이 유지됩니다. 복원은 확인 후 적용합니다. |

복원은 기존 레코드·보기 ID를 유지하면서 새 버전을 추가합니다. 페이지에서 연결한 보기도 원본의 복원 결과를 표시합니다. 롤업과 수식은 현재 데이터에서 다시 계산합니다. 현재 스키마나 관계 대상과 맞지 않는 버전의 복원은 거부되며 기존 값과 이력이 보존됩니다.

## 저장과 업그레이드

SQLite에 레코드·보기 이력 테이블을 추가했습니다. 업그레이드 시 유지된 데이터를 이력의 시작점으로 삼습니다. 레코드를 삭제하면 해당 레코드의 이력도 삭제됩니다. 기본 내장 업무 데이터베이스에는 기존 편집 방식이 적용됩니다.

[Windows 실행과 DB 복사본 검증](../RUN_LOCAL.md)을 참고하세요.

## 검증

- Linux의 `python -m pytest -q`에서 테스트 59개와 서브테스트 716개 통과.
- 기존 Chromium 회귀 스크립트 7개와 신규 `tests/browser/workspace_v130.py` 통과. 신규 검증은 레코드 속성·보기 설정 복원, 연결된 페이지에서 반영, 서버 재시작 후 이력을 확인합니다.
- v1.2.0 후보의 합성 SQLite 복사본으로 업그레이드했습니다. 기존 레코드·보기와 페이지 연결, SQLite 무결성·외래 키 및 원본 해시를 확인했습니다.
